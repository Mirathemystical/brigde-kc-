# BRIDGE KC — Presentation Outline

## 1. Opening (30 sec)
“BRIDGE KC helps people move from searching for support to taking a clear next step.”

## 2. The problem (60 sec)
Describe the problem hypothesis and share anonymized interview evidence. Do not present assumptions as proven facts.

## 3. Who we designed for (45 sec)
Introduce the primary user group and key barriers discovered through interviews.

## 4. Live demo (2 min)
1. Search or filter resources.
2. Choose a goal.
3. Review suggested next steps.
4. Mark progress and explain what is stored locally.
5. Point out source-verification status and prototype limitations.

## 5. What we learned (60 sec)
Share test count, task completion, common friction points, and one change made based on feedback.

## 6. Impact and limitations (45 sec)
Report verified resources, usability findings, and evidence of people reaching a useful next step. Be clear about what has not yet been measured.

## 7. Leadership (45 sec)
Explain how the team divided work, handled blockers, incorporated feedback, and made scope decisions.

## 8. Ask / next phase (30 sec)
Request introductions to community partners, feedback on resource coverage, and approval to run another small user test.

## Presentation rule
Use real evidence, anonymize participants, cite resource sources, and never claim the prototype uses AI unless an actual AI system has been implemented and evaluated.
